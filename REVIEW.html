1. Executive summary

A genuinely strong, coherent corpus of AI and quantum-computing ethics standards, written in the register of an international standards body — RFC 2119 normative language, axiom→requirement→evidence traceability, risk tiering, audit & certification, case studies, and an Astro Starlight site to publish it. The conceptual architecture (Axioms → Governance → Technical Standards → Controls → Assurance) is clear and actually followed. The best documents (autonomy_and_human_control, supply_chain_and_provenance, fairness_and_justice) would not look out of place in a real ISO/IEC working draft.

The central problem is internal consistency, not quality. The corpus mandates structures in its own normative documents — a Traceability Table per standard, a Change Log per standard, one canonical document per topic — and then fails those mandates in roughly a third of its own files. Two visible "generations" of documents coexist in the quantum section, creating duplicate standards with conflicting requirement IDs. And the site has two config choices likely to fail to build against the pinned Starlight version.

Overall verdict: high-quality content, ~85% polished, held back by self-consistency gaps and a few fixable build risks. Nothing is deep; most is an afternoon of cleanup. The single most important fix: the corpus violates its own MUST requirements — for a document whose explicit purpose is to prevent "paper governance" and "ethics washing," that is the gap most likely to undermine its credibility with the regulators and auditors it is courting.

2. What's strong (keep doing this)

  • Clear normative architecture. The five-layer stack is stated and followed; risk tiers (0–3) are defined once and referenced consistently.
  • Traceability as a first-class idea. ETHICAL_TRACEABILITY.md turns "ethics" into an auditable requirement→axiom→evidence mapping and explicitly targets ethics washing. Where the tables exist, they're good.
  • The fuller standards are rigorous. emergency_powers_and_safeguards, independent_ethics_review, supply_chain_and_provenance, environmental_and_resource_ethics, autonomy_and_human_control, fairness_and_justice, healthcare_ai, monitoring_and_incident_response, certification_and_labeling, ethical_metrics are consistent and evidence-oriented.
  • Honest self-awareness. FAILURE_MODES.md and founders_commentary.md pre-empt the obvious critiques.
  • Healthy site hygiene. Dependabot is active, secrets handling is documented, and the sync script resolves paths relative to itself.
  • Clean link integrity. Every backtick-quoted *.md path in the corpus resolves to a real file.

3.2 Missing Change Logs. VERSIONING.md says every standard MUST keep a Change Log. 8 lack one: consultation_framework, governance_model, international_alignment, control_matrix, risk_classification, audit_methods, certification, metrics.

Fix: either bring these up to the mandated template, or soften the mandate and explicitly exempt index/meta docs. Whatever you choose, the rule and the corpus must agree — a standards body that fails its own conformance check has no answer when an auditor points it out.

HIGH Duplicate, competing quantum standards

Two parallel documents per topic, with different requirement-ID schemes and no statement of which is canonical:

Topic"Light" doc (1st gen)"Full" doc (rewrite)

The control matrix, case studies, and FAILURE_MODES.md all reference the light versions, leaving the fuller, more rigorous versions orphaned from navigation. A reader can't tell which document is authoritative.

Fix: pick one canonical doc per topic (keep the fuller ones), migrate unique requirements, repoint all references to the surviving IDs, and delete/redirect the loser. This is a normative ID change — version it accordingly.

risk_classification.md cites AI-F-3 ("equity impact assessment"), but the fairness standard was renamed to fairness_and_justice.md with AI-FJ-* IDs; the equity impact assessment is now AI-FJ-11. AI-F-3 exists nowhere in the corpus.

MED No LICENSE file

For a corpus whose stated ambition is global adoption and submission to standards bodies, reuse/redistribution/contribution terms are legally undefined — a real blocker for institutional adoption and awkward given the emphasis on provenance and rights elsewhere.

Fix: add an explicit license — CC BY 4.0 (or CC BY-SA) for the standards text; dual-license with MIT for site/ code if you want code terms to differ.

MED Site/build configuration risks (verify — no build was run)

Both likely fail or misbehave on the pinned Starlight ^0.32.0:

1. Deprecated social object form in astro.config.mjs. Starlight moved social to an array of link objects around 0.32:

social: [{ icon: "github", label: "GitHub",
  href: "https://github.com/adamsdsit/ai-quantum-ethics-standards" }]

2. Hand-rolled docs collection in src/content.config.ts uses legacy type: "content" and a bare Zod schema that strips Starlight's frontmatter. Astro 5 + Starlight expects:

import { docsLoader } from "@astrojs/starlight/loaders";
import { docsSchema } from "@astrojs/starlight/schema";
const docs = defineCollection({ loader: docsLoader(), schema: docsSchema() });

Fix: run a clean cd site && npm ci && npm run build in CI and resolve whatever these surface.

LOW Repository hygiene & consistency

  • No CI (.github/workflows absent) — yet Dependabot keeps bumping Astro/Starlight with no automated build to catch a bad bump.
  • No community-health files (CODE_OF_CONDUCT, issue/PR templates) — at odds with a participation-first governance model.
  • README map incomplete — omits e.g. non_derogation_and_red_lines, supply_chain_and_provenance, environmental_and_resource_ethics, consultation_framework, the full 02_ai_standards/ list, and SECURITY.md.
  • Two-tier template inconsistency (## Applicability vs ## 3. Scope; 9-section template vs lighter headers) reads as unfinished. Aligning all standards to standard_template.md fixes this and §3.1/§3.2 at once.
  • PROMPT_TEMPLATES.md is internal scaffolding shipped in a public, regulator-facing corpus — consider moving under meta/.

4. Guardrails so issues don't recur

4.1 Add CI (.github/workflows/ci.yml): on every PR, install site/, run astro build, fail on errors. Catches the social/collection issues and bad Dependabot bumps.

4.2 Add a self-compliance check (~30 lines, in CI): assert every *.md in 01_–05_ contains a Traceability Table and Change Log, and that every …-N requirement reference resolves to a defined ID (would have caught AI-F-3). This makes the corpus mechanically verify the very discipline it preaches.
